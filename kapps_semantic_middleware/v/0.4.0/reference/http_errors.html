HTTP errors#

The HTTP status that each typed error answers on the middleware’s own routes, and the body of every error answer. Which action each type asks for is on When a call fails: the error map.

The HTTP status of each typed error on KSM’s own routes, and the body of every error answer.

A remote caller sees only the status and the body, so the status tells it what the error’s type tells a caller in Python. The docs’ error map gives each action one status:

  • Repair, 500: OGMOntologyError, DeploymentError, AuthenticationError, TripleStoreAccessError.

  • Retry, 503: TripleStoreUnavailableError, OperationReceiverUnavailableError, NotificationReceiverUnavailableError.

  • Refresh, 409 or 404: PreconditionFailedError (409), OGMNotFoundError (404, the addressed instance does not exist).

  • Refused, 422: ShaclValidationError, OGMDataError.

  • Fix the call, 400: request validation, OGMUsageError.

Only typed errors are mapped. A bare built-in (ValueError, TypeError, RuntimeError) and any type the list does not name answer 500: their type tells no action, and a status for them would be an interpretation. No answer carries Retry-After: no error carries a retry hint.

The body of every error answer is {"error", "detail", "report"}: the type name, the original message, and the store’s raw report (a ShaclValidationError’s) or null. Nothing is parsed. For KSM’s own HTTPException (an unknown dashboard box, an absent owner, a wrong log level), error is the status’s reason phrase. For a request that fails validation, error is RequestValidationError and detail is FastAPI’s list of errors.

Where the map sits. FastAPI’s exception handlers are app-wide, and an app-wide handler would also change the framework’s routes: its workflow routes answer 409 for a RuntimeError and a plain 500 for anything else, and they keep those answers. So the map sits on KSM’s own routers, as the route class TypedErrorRoute. Request validation is the one app-wide handler, install_validation_handler, because FastAPI offers it only for the whole app; it covers the framework’s routes too.

Bases: APIRoute

A route that answers a typed error with the status of its action, in the error body.

Pass it to a KSM router as APIRouter(route_class=TypedErrorRoute); include_router keeps it. A RequestValidationError goes on to the app’s handler, so that the framework’s routes and KSM’s answer it alike.

kapps_semantic_middleware.http_errors.install_validation_handler(app: FastAPI) → None[source]#

Answer a request that fails validation with 400 and the error body, on every route of app.

FastAPI’s default is 422, which means Refused in KSM’s map. Installing it twice is harmless.

kapps_semantic_middleware.http_errors.status_for(error: BaseException) → int[source]#

The status of error’s action: that of the first mapped class in its MRO, else 500.

The MRO, not an isinstance chain, decides, because several types have two bases that the order of a chain would weigh wrongly: ShaclValidationError is a TripleStoreResponseError, and each OGM category is also a ValueError.
