Validation report#

Reading the store’s validation report, the report of a ShaclValidationError, and showing a refused write readably.

What the store’s validation report says, read as RDF, and each refused write shown readably.

When the store’s shapes refuse a write, the triplestore interface raises ShaclValidationError, and its report is the store’s validation report, verbatim: N-Quads, as the store sends it. The refusal is the error’s type. This module only reads what the report says, as RDF, never as text: the store puts the source shape’s own description into the report, path included, so every name can appear in the text while no result names it.

It reads a report three ways:

  • readable_results, for a person: each result’s message, severity, focus node, path, value, source shape and source constraint component, each a term, short and full.

  • validation_results, for a caller that compares: each result’s focus node, path and source shape as full IRIs, the path in SPARQL property path syntax.

  • rule_names, for a log line: each source shape at its focus node, by local name.

A text that is no RDF names no result. A caller still carries it verbatim.

A write of a middleware instance that the store’s shapes refuse is a RefusedWrite: the time, the verb that wrote (commit, create or handover), the rules that the report names, and the report. render_refused_write shows one as HTML, for a person: its first line visible, and the results and the whole report behind an expander.

The middleware keeps the newest refused writes of its instance in memory, and logs each one as one record at INFO on this module’s own logger, kapps_semantic_middleware.validation_report. The first line of the record says what was refused and by which rules; the following lines hold the readable results and the whole report.

class kapps_semantic_middleware.validation_report.Term(short: str, full: str)[source]#

Bases: NamedTuple

One term of a result for a person to read: short, and full beside it, as for a tooltip.

An IRI is short by its local name, the part after its last # or /, and full as it is. A path is in SPARQL property path syntax both ways, each IRI by its local name in one and whole in the other. A literal is short by its lexical form, and full in N-Triples syntax, with its datatype or its language. A blank node is short as blank node. The message of a result that gives several holds each of them on a line of its own, in both forms.

The short form is for display only: it is never compared, and never turned back into an IRI.

kapps_semantic_middleware.validation_report.readable_results(report: str) → list[ReadableResult] | None[source]#

Every result of report as a person reads it, read as RDF, in the order of their source shapes, then their focus nodes. None when report is no RDF, which a caller then shows verbatim.

kapps_semantic_middleware.validation_report.render_refused_write(refused: RefusedWrite) → str[source]#

One refused write as HTML, for a person to read.

Its first line is always visible: the time, the verb, and the rules, each source shape at its focus node, by local name. An expander holds a table of the results, one block of rows for each, and the whole report, verbatim, with its line breaks. Each term of the table shows its local name, with the full term as its tooltip. Every value is escaped, so a value that holds markup is shown as text.

The expander has an id of its own, the same for the same refused write, and asks htmx to preserve it: a box that polls swaps its fragment in again, and an expander that the reader opened stays open, because a refused write never changes once it is recorded.

kapps_semantic_middleware.validation_report.rule_names(report: str) → list[str][source]#

The rules report names, for a person to read: each source shape at its focus node, by local name, such as PossessionShape at Module2, in order. The local names are for display only: a caller that compares reads validation_results.

kapps_semantic_middleware.validation_report.validation_results(report: str) → set[ValidationResult][source]#

Every validation result of report, read as RDF.

A statement of the report may name a graph; the results are read across all of them. A text that is no RDF has no result.
