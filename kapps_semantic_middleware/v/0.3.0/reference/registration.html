Registration#

Putting an asset and its capabilities into the graph.

Graph-write core of the KAPPS Semantic Middleware.

Every knowledge-graph write goes through the OGM (OGM.create / OGM.commit). This is the architecture’s single validated write path. No write issues raw SPARQL UPDATE. Reads may use the triple-store access module (ogm.db) directly. The architecture permits this.

Only one direction of each inverse relation receives materialization. The direction belongs to the newly-created instance (e.g. a workflow svc:isWorkflowOf, a capability svc:realizedByWorkflow). The container-side inverses (svc:hasWorkflow etc.) are OWL-inferable. They receive no write. Each registration is a clean single-instance OGM.create rather than a read-modify-write append onto a growing multi-valued property. Queries in this module therefore use the materialized (instance-owned) direction. The one exception is the resource’s cfc:hasCapability, which Core gives the resource: it is written through OGM.commit as an Append, which adds the link and removes none, in the same commit as the Capability it links, so no commit holds a Capability without its resource (see _register_capability).

kapps_semantic_middleware.registration.normalize_address(address: str) → str[source]#

Normalize an instance address. Trivially different spellings become one deployment.

Lowercase the scheme and the netloc (host names are case-insensitive, paths are not). Strip a trailing /. Without this, http://Host:8000/ and http://host:8000 would mint two Service nodes for one process. This discriminator prevents exactly that orphaning.

kapps_semantic_middleware.registration.mint_service_iri(resource_iri: IRI, address: str) → IRI[source]#

Mint the Service IRI for one middleware instance: {resource_iri}_service_{address}.

The discriminator is the instance normalized address mangled with IRI.lined. This satisfies two requirements at once. It is stable across restarts of the same deployment (a returning instance re-adopts its node). It is distinct between concurrent instances (a controller and a monitor on one resource do not overwrite each other svc:hasAddress and heartbeat). lined rather than a hash. Production IRIs remain back-resolvable. IRI.from_lined reads the address off the node IRI.

address is required. A default would silently reinstate the shared node.

Raises:

ValueError – If address is not an absolute http(s) URL.

kapps_semantic_middleware.registration.assert_class_registered(ogm: OGM, class_iri: IRI, base_iri: IRI, named_graph: IRI | None = None) → None[source]#

Assert a class pre-exists as the required kind.

Raises:

OntologyGroundTruthError – If the class is missing or not the required subclass.

kapps_semantic_middleware.registration.register_service(ogm: OGM, *, resource_iri: IRI, service_iri: IRI, service_class: IRI, address: str, named_graph: IRI | None = None) → None[source]#

Register a Service instance for a resource. Set its base address and a first heartbeat.

The address and svc:hasLastHeartbeat (now) are written in one commit. A Service with an address is stale to the watchdog when its heartbeat is missing or old, so an address written alone would let a sweep that runs before the heartbeat loop’s first beat deregister a Service that is starting, or one that restarts after its old heartbeat aged past the threshold.

Raises OntologyGroundTruthError if service_class is not svc:Service or a subclass.

kapps_semantic_middleware.registration.register_workflow(ogm: OGM, *, resource_iri: IRI, service_iri: IRI, workflow_iri: IRI, workflow_class: IRI, capability_iri: IRI, capability_class: IRI, endpoint: str, named_graph: IRI | None = None) → None[source]#

Register a Workflow instance, its Capability instance, and their links.

The Workflow owns svc:isWorkflowOf (-> service) and svc:hasEndpoint. The Capability owns svc:realizedByWorkflow (-> workflow). The resource links to the Capability it provides (cfc:hasCapability, Resource -> Capability). The resource provides the Capability. Raises OntologyGroundTruthError if the classes are not the required subclasses.

kapps_semantic_middleware.registration.register_state_property(ogm: OGM, *, resource_iri: IRI, service_iri: IRI, state_property_iri: IRI, state_property_class: IRI, capability_iri: IRI, capability_class: IRI, endpoint: str, named_graph: IRI | None = None) → None[source]#

Register a StateProperty instance, its Capability instance, and their links.

The StateProperty owns svc:isStatePropertyOf (-> service) and svc:hasEndpoint. The Capability owns svc:providedByStateProperty (-> state property). The resource links to the Capability it provides (cfc:hasCapability). Only the stable endpoint receives write. The live value receives no persist.

kapps_semantic_middleware.registration.deregister_service(ogm: OGM, service_iri: IRI, named_graph: IRI | None = None) → None[source]#

Remove a Service reachability (address + all workflow/state endpoints).

Endpoints receive removal via OGM.commit (the validated write path). The workflows/state- properties to clear are found via a read on the instance-owned inverse (svc:isWorkflowOf / svc:isStatePropertyOf). Structural triples and rdf:type are preserved.

The endpoints go first and the address last, each in its own commit. A deregistration that stops halfway (a store error) leaves the address, so the Service is still found by its address (as stale, by the watchdog) and the next deregistration finishes it; the reverse order would leave endpoints that nothing finds again.

kapps_semantic_middleware.registration.find_stale_services(ogm: OGM, max_age_seconds: float, *, now: datetime | None = None, named_graph: IRI | None = None) → list[IRI][source]#

Find reachable-but-silent Services whose heartbeat has gone stale (a read).

A service is stale if it currently has an svc:hasAddress but either has no svc:hasLastHeartbeat or its latest heartbeat is older than max_age_seconds. Services are identified by svc:hasAddress presence (real services are subclass-typed, so rdf:type svc:Service would not match).

kapps_semantic_middleware.registration.sweep_stale_services(ogm: OGM, max_age_seconds: float, *, now: datetime | None = None, named_graph: IRI | None = None) → list[IRI][source]#

Deregister every stale Service. Fail the Operations of its resource that are stranded.

Alongside removal of a dead resource reachability, the watchdog marks failed the queued/running Operations of that resource that no surviving Service can take. Work addressed to a resource that will never return does not hang forever. Returns the Service IRIs it deregistered; one skipped on a store error is left for the next sweep and not returned.

The decision is per Operation (find_stranded_operations()), live meaning a Service with an svc:hasAddress and an svc:hasLastHeartbeat within max_age_seconds of now: a queued Operation is stranded when its Capability is realized by no live Service of its resource; a running one when the Service of the Workflow that claimed it (svc:executedByWorkflow) is not live, or no claimer is recorded. The stale Service is not live by definition. So a stale monitor does not fail the queue of a live controller sibling that realizes its Capability, a live monitor that realizes no Workflow does not shield the queue of a dead controller, and a dead claimer’s running Operation is failed even when a live sibling realizes its Capability (that sibling would never run it). The stale Service is deregistered either way. The startup reconstruction of a queue (SemanticMiddleware._reconstruct_queue) decides its running Operations with the same predicate.

kapps_semantic_middleware.registration.mint_operation_iri(operation_class: IRI) → IRI[source]#

Mint a unique Operation instance IRI under the operation-class namespace.

Operations are per-dispatch. Each dispatch mints a fresh IRI (unlike the deterministic registration IRIs).

kapps_semantic_middleware.registration.create_operation(ogm: OGM, *, operation_iri: IRI, operation_class: IRI, capability_iri: IRI, status: str = 'queued', data: dict | None = None, named_graph: IRI | None = None) → None[source]#

Create an Operation individual for dispatch. Address it to a target Capability.

The whole Operation is written in ONE OGM.commit: its rdf:type, its single-valued cfc:implementsCapability link, svc:hasOperationStatus, and data, whose properties the Operation’s class must declare: kapps_ogm refuses a property that the class does not declare, with OGMDataError. Its class scope names every property it sets, so none lies outside the scope. issue_operation() does not call this: it creates the Operation with mw.create() under the operation scope. This writer is kept for existing callers, such as tests that seed an Operation. The IRI must be new: the store must hold no statement about it yet, or the store’s refusal PreconditionFailedError is raised, and nothing is written. The Resource->Capability cfc:hasCapability link written at registration is a separate, multi-valued property of the resource, written through the OGM as an Append in the Capability’s own commit by _register_capability.

kapps_semantic_middleware.registration.resolve_dispatch_target(ogm: OGM, capability_class: IRI, target_resource: IRI | None = None, named_graph: IRI | None = None) → Tuple[IRI, IRI, str][source]#

Resolve a reachable receiver for a Capability class.

Bind a Capability instance of capability_class realized by a Workflow whose Service has a live svc:hasAddress: Capability --realizedByWorkflow--> Workflow --isWorkflowOf--> Service --hasAddress. If target_resource is given, the Service is pinned to that resource (svc:isServiceOf). The bound Capability instance is what the dispatched Operation will cfc:implementsCapability.

Returns:

Tuple of (capability_instance_iri, service_iri, service_address).

Raises:

  • OperationReceiverUnavailableError – If a Workflow realizes a Capability of the class, but no Service of it has an address now (Retry). A second read, made only when the first finds no live Service, tells this case from the next.

  • CapabilityNotRealizedError – If no Workflow realizes a Capability of the class (Repair).

kapps_semantic_middleware.registration.resolve_operation_workflow(ogm: OGM, operation_iri: IRI, named_graph: IRI | None = None) → IRI[source]#

Resolve an Operation to the Workflow that realizes its Capability, WITHOUT require of a live endpoint. This is the provenance resolver used by pull-and-run so executedByWorkflow receives record even if the workflow svc:hasEndpoint was deregistered mid-run.

Raises:

CapabilityNotRealizedError – If no Workflow realizes the Operation Capability (Repair). It is an OperationResolutionError.

kapps_semantic_middleware.registration.find_resource_operations(ogm: OGM, resource_iri: IRI, statuses: list[str], named_graph: IRI | None = None) → list[IRI][source]#

Find a resource own Operations whose svc:hasOperationStatus is one of statuses.

Ontology-backed traversal: an Operation implements a Capability (cfc:implementsCapability). The resource provides that Capability (cfc:hasCapability). Both links persist across a restart. This works at early startup before re-registration. Explicitly does NOT match on IRI names.

Parameters:

  • ogm – The OGM instance.

  • resource_iri – The resource whose queue to inspect.

  • statuses – Iterable of status strings to filter (e.g. ["queued", "running"]).

  • named_graph – Optional named graph for the read.

Returns:

List of Operation IRIs matching the criteria.

kapps_semantic_middleware.registration.find_stranded_operations(ogm: OGM, resource_iri: IRI, statuses: Sequence[str], max_age_seconds: float, now: datetime | None = None, named_graph: IRI | None = None, *, excluding: Sequence[IRI] = ()) → list[IRI][source]#

Find a resource own Operations, in one of statuses, that no live Service will finish.

A Service is live when it has an svc:hasAddress and an svc:hasLastHeartbeat no older than max_age_seconds before now, and is not in excluding. The Operations are the resource own, as find_resource_operations() finds them (cfc:implementsCapability and cfc:hasCapability). Two rules, one read:

  • A running Operation is stranded when the Service of its executor is not live: the Workflow recorded at the claim (svc:executedByWorkflow) belongs (svc:isWorkflowOf) to no live Service. A running Operation without a recorded executor (written by a claim that names none) is stranded. No other Service takes up a running Operation, so only its claimer counts.

  • An Operation in any other status (queued) is stranded when its Capability is realized by no live Service of its resource: no Workflow that realizes the Capability (svc:realizedByWorkflow) belongs to a live Service of the resource (svc:isServiceOf). The joins are those of discovery (resolve_dispatch_target()), plus the heartbeat.

The watchdog sweep and the startup reconstruction of a queue (for its running Operations) both decide with it. The reconstruction takes up its queued Operations without it. A restarting instance’s re-registration writes a fresh heartbeat with its address (register_service()), so a sweep after it counts the instance as live.

Parameters:

  • ogm – The OGM instance.

  • resource_iri – The resource whose Operations to inspect.

  • statuses – The statuses to filter (e.g. ["queued", "running"]).

  • max_age_seconds – The staleness threshold: a heartbeat older than this is not live.

  • now – The time the threshold counts back from. Defaults to the current time.

  • named_graph – Optional named graph for the read.

  • excluding – Services that never count as live, whatever their heartbeat. A restarting instance names its own Service here: its heartbeat may still be fresh from before the crash, and the running Operations it claimed then are orphans.

Returns:

List of the stranded Operation IRIs.

kapps_semantic_middleware.registration.services_of_resource(ogm: OGM, resource_iri: IRI, *, reachable_only: bool = False, named_graph: IRI | None = None) → list[IRI][source]#

Every Service bound to a resource, via the instance-owned svc:isServiceOf.

A Service IRI carries an instance discriminator, so it cannot be reconstructed from a resource IRI alone; this read finds it instead. svc:isServiceOf is many-to-one. Consumers must not assume the answer has exactly one element. A controller and a read-only monitor on one resource are two Services.

Parameters:

  • ogm – The OGM instance.

  • resource_iri – The resource whose services to find.

  • reachable_only – Keep only Services that currently carry an svc:hasAddress. A deregistered instance keeps its individual but loses its address. This is the reachable-now set rather than the ever-registered set.

  • named_graph – Optional named graph for the read.

Returns:

List of Service IRIs.

kapps_semantic_middleware.registration.mark_operation_failed(ogm: OGM, operation_iri: IRI, reason: str, named_graph: IRI | None = None) → None[source]#

Transition an Operation to failed with a reason via the OGM atomic commit path.

Use to reclaim an orphaned running Operation (a resource crashed mid-execution) or to sweep a dead resource stranded Operations. Recovery is never a silent physical replay. The Operation goes to failed. A planner decides whether to re-dispatch.

kapps_semantic_middleware.registration.reachable_service_addresses(ogm: OGM, resource_iri: IRI) → list[Tuple[IRI, str]][source]#

Every reachable Service of a resource, with its svc:hasAddress.

The reachability rule of services_of_resource(..., reachable_only=True): a Service is reachable while it carries an svc:hasAddress. The address is read in the same query, so a Service cannot lose it between two reads. A resource may have several reachable Services (one for each middleware instance bound to it); the caller decides what that means.
