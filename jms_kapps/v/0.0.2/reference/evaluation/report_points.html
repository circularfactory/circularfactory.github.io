jms_kapps.evaluation.report_points#

The report points: the runs of the “after” series go on around the clock, and other use of the KIT GraphDB may overlap them. The report groups the runs by hour, marks a run that overlaps a live check or whose server watch shows other activity, shows the global page cache’s hit share, counts the runs with a deadlock alarm apart and shows each dead heartbeat. Interim names: every name here, the files marks.csv, hours.csv, page_cache.csv, deadlock_alarms.csv and dead_heartbeats.csv, the option –live-checks and the summary’s key points.)

What a run keeps (points_of, in the run’s summary, so that a record and its spans are read once): the window and the hour of its start (UTC), whether the server watch shows other activity, the page cache’s deltas, each deadlock alarm and each dead heartbeat. Only the overlap with a live check is worked out when the report is built, because the live-check log grows while the runs go on.

The live-check log is the orchestrator’s file of JSON lines, one at the start and one at the end of each live check on the KIT GraphDB, with the fields event (start or end), at (ISO 8601, UTC, seconds), check (free text) and repository. The report reads it from the path of –live-checks; without a path, or where the file cannot be read, every mark says no data. A line that is no event is left out. A start pairs with the next end that has the same check and repository; a start without an end counts as running until the report is built. A run overlaps a check when its window and the check’s span share a moment (touching counts).

Other activity. The server watch reads the monitoring view of every repository at the run’s start and at the drain’s end (server.repository_monitors_at_the_start and …_at_the_drain_end). A run is marked when, for a repository other than its own, a cumulative counter (epoolReads, epoolWrites) rose between the two reads, or a gauge (openConnections, activeTransactions) was above zero at either. A repository that was not read (read: false, an inactive one), a refused view and a counter that fell (the server restarted) are no activity. Where no other repository could be read at all, the mark says no data, not none.

The page cache. The deltas of the global page cache’s hits and misses between server.structures_at_the_window_start and server.structures_at_the_drain_end. A negative delta (the counters reset when the server restarted), a refused view or a view without the two counters makes that run’s share no data. The hit share of a prefill is the sum of the hits over the sum of the hits and misses of the valid runs with data.

The dead heartbeat. A heartbeat is a participant’s write of its last-heartbeat time: a store write that the store accepted and whose step category is heartbeat update (report_steps); there are no heartbeat spans of their own. A participant’s heartbeat is dead when its last heartbeat write started more than the live-heartbeat age (live_heartbeat_age_seconds of the record’s run settings; 90 s where the record has none) before the start of its last other span. A participant that wrote no heartbeat at all is not listed. A run without spans has no data.
