jms_kapps.evaluation.summary#

What the table of a spec (table) and the ramp’s broken rule (ramp) read of one record: its run, whether it counts, and its measures, without the text of its store requests. A record holds every store request with its text, so a folder of records is read one record at a time, and only its summary is kept.

Which runs count. A run counts in the statistics when it completed and its record does not say it is invalid. A run that a check found invalid, a run that failed, and a run that a stop signal ended are left out, and the table lists each with why.

The run kinds. A run of use case 2 is of the run kind uc2, with the wrapper, or uc2-unwrapped, without it. A store-only baseline is of the run kind baseline: it replays the store requests of one recorded run of use case 2, so it belongs to that run’s configuration. Its record names the run it replays in its field replayed_run, by that run’s run_id.

The measures read. Each latency, rate and share comes from the measured window alone, as the record’s measures hold it: the latencies of the commits the store admitted; the latencies of the store requests that the store accepted, logins left out, since a baseline replays none; the completed writes per minute and the transports ended per minute; and the store requests, those refused, those that timed out and those whose connection dropped, and the three together (refused or unanswered). A request that a record written before the rename says “timed out” is classified by its error (store_requests.outcome_of), so a dropped connection of such a record counts as connection dropped; no record file is changed. The refusals for want of heap count under the load: in the warm-up, the window and the drain. Such a refusal is a signal of the store at that load, wherever in the load it comes; one before the load’s start, as at the participants’ start, is a signal of the store’s size, not of the load. A baseline has neither a warm-up nor a drain, and the requests it sends before its window are no load, so its window alone counts. A measure the record does not hold is None: a run without the wrapper has no commit and no store request, and a baseline has no transport. Then each box still waiting after the drain (stuck), each failed box, each with its place and reason, each spawn the WarehouseManagementSystem refused, with its reason and where it was known, and the completion matcher’s reads.
