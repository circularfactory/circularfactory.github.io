jms_kapps.common.api_docs#

A process’s API docs by relative paths, so that they work under any path the process is reached at.

FastAPI’s docs page, at /docs, loads the API’s description from /openapi.json, a path from the root of the server, and its “Try it out” sends each request to the root of the server too. Through the page of a run, which passes each process’s pages through under /p/<id>/ (passthrough), both miss the process. Every other page of a run asks for what it needs by a relative path, and so do the docs here: the page loads the description next to itself, and the description names its server ., the folder it was loaded from. At the process’s own address that is its root, as before.

Nothing needs to know the path in front: not the process, which is started before the page of the run serves it, and not that page, which rewrites nothing that passes through.

jms_kapps.common.api_docs.relative_api_docs(app: FastAPI) → None[source]#

Serve app’s API docs by relative paths, in place of FastAPI’s own docs page.

The page stays where it was, with the same title and settings, and lists the same routes; only the paths it names change. An app without docs is left as it is.
