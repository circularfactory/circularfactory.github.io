jms_kapps.uc2.module_memory#

What one FlexConveyorModule knows of its own work, kept in its memory.

Its dashboard renders this memory and the module’s fault switches, and nothing else, so an open tab causes no load: no read of the graph and no call to a peer. The module writes it as it works, from what it reads and answers for its work anyway: its decisions, with the connections each one read and the Reserve refusals that followed, and the box it holds. Its process adds one read of its own when the module starts: the connections, so that the dashboard draws them before the first decision, and the boxes the module possesses, so that a restarted module shows the box it holds.

Bases: object

Where the module decided to send a box, and when.

next_module is the module it chose, or None where it chose none: the box is on its destination, or no path leads there. ties are the modules it could also have chosen, on a shortest path as short, which lost to the lowest IRI, or to the module reserved ahead. refusals are the Reserve refusals of the next module that followed, in order. detour is the one other module it would try when the next module declines, detour_refusals that module’s refusals, and detoured whether the box went there. retries counts the times it waited and asked again.

class jms_kapps.uc2.module_memory.ModuleMemory[source]#

Bases: object

What a module knows of its own work: its newest decisions, the connections it read last, and the box it holds.

It holds a box from the moment it knows it possesses the box: its start read finds the box in its possession; its Receive confirms the box’s arrival, after the giving module’s handover committed the change of possession; the bound of its reservation finds the box in its possession, though no Receive came; or, at the origin, the store admits the box’s transport running, which it does only while a FlexConveyorModule possesses the box, and the WarehouseManagementSystem created the box on the origin before it notified it. A transport merely assigned to the module is no such knowledge. It holds the box until the move of the box off it has ended, so during a move the box is still the giving module’s here, where the graph already names the receiving module its possessor.
