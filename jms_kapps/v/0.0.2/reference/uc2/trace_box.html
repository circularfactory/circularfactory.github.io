jms_kapps.uc2.trace_box#

jms-uc2 trace-box: every change of a box’s possession, read back from the triple store’s history.

A handover overwrites the box’s link to its possessor’s possession state, so the knowledge graph holds only the present possessor. The triple store’s history holds every change, each with its transaction and its time (history). This command shows one box’s way through the station from there. On a disposable dataset of the configured store it:

  1. seeds the topology line, four modules one after another, and turns the dataset’s history collection on;

  2. starts the four modules and the WarehouseManagementSystem through the run core, without the Launcher, and waits until each is ready;

  3. spawns one box through the WarehouseManagementSystem’s spawn workflow, from the line’s entry module to its exit module, with the normal transit time;

  4. waits until the box’s transport is done and the WarehouseManagementSystem has logged the box back, then stops every participant;

  5. reads the change list of the box’s possession link, of the transport’s status and of its assignment (cfc:executedOn), and groups the changes by transaction: one row each.

It prints the rows as one table, with each time in UTC and in the server’s local time, and writes them as JSON (–out, trace-<box>.json in the current folder by default), with a cross-check: the possessors in the order of their transactions, against the handovers the participants logged: the WarehouseManagementSystem’s spawn onto the origin, each module’s convey to the next, and the WarehouseManagementSystem’s take-back. It exits 0 when the two agree, and 1 otherwise, or when the store cannot be reached, the run does not start, or the transport does not end.

The history collection stays on (history), so the command takes only a name that starts with ogm-disposable-. It works on a dataset whose collection is on already, and again on the same dataset: the box’s own name keeps the runs apart.

jms_kapps.uc2.trace_box.trace(topology: Topology, graph: RunGraph, supervisor: Supervisor, participants: Sequence[Participant], *, history: Queryable, spawn: Callable[[IRI, IRI], tuple[IRI, IRI]], status: Callable[[IRI], str | None], dataset: str, out_path: Path | None = None, transit_seconds: float = 3.0, out: TextIO | None = None, interval: float = 0.5, transport_timeout: float = 120.0, take_back_timeout: float = 30.0) → int[source]#

Run one box over topology and print its trace from the history to out (the current sys.stdout where None), and write it to out_path, default_out where None. Returns 0 when the history agrees with the logs, and 1 otherwise.

Parameters:

  • graph – The run’s graph, which the seed clears.

  • supervisor – The supervisor of participants, the modules of topology and the WMS.

  • history – Where the history is read: the run’s dataset.

  • spawn – Spawns one box from an origin to a destination, through the WarehouseManagementSystem; returns the box and its transport.

  • status – The status of a transport, as the graph holds it now.

  • dataset – The name of the run’s dataset, for the record.

Raises:

  • LaunchFailed – If the run did not start.

  • NotReady – If a participant did not get ready.

  • TraceFailed – If the spawn was refused.

jms_kapps.uc2.trace_box.run(dataset: str, *, out_path: Path | None = None, transit_seconds: float = 3.0) → int[source]#

Trace one box on dataset of the configured store. Returns the exit code of trace, or 1 with the reason on stderr when the name is not a disposable one, the store cannot be reached, another run is live there, or the run does not give a box.
