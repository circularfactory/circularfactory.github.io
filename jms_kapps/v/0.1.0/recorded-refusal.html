A recorded refusal: a handover onto an occupied module#

One refused commit, recorded from a real run of the write path of use case 2: module 1 hands box B to module 2 while module 2 holds box A, without asking module 2 to reserve itself, as a module does with skip-reserve armed (see Fault refusals). The handover is the middleware’s: its entry commits the change of possession and the transport’s reassignment through the Object-Graph Mapper (OGM) and the triple store access module, and the triple store validates the commit against the shapes of use case 2 at commit. The store refuses it at :FlexConveyorModulePossessionShape, at most one box per module, with the validation report below, and nothing changes.

The page, the report verbatim (skip-reserve.nq) and its Turtle copy (skip-reserve.ttl) are written by one script, scripts/record_uc2_refusal.py, in one run on the dataset it is given, which it clears. The run is deterministic: a rerun gives the same report, apart from the blank-node labels the store gives it, and tests/test_uc2_recorded_refusal_live.py reruns it and compares the two as RDF graphs.

The setup. The seed of two modules, module 1 connected east to module 2, each served as a middleware instance as in a run, so that each registers its BoxTransportCapability (fci:Module1_capability_box_transport and fci:Module2_capability_box_transport). Then, written directly as a seed writes, box A on module 2, with its transport executed on module 2, and box B on module 1, with its transport from module 1 to module 2, running and executed on module 1; each transport implements the capability of the module it is executed on. Then module 1’s giving side hands box B to module 2, with the entry a hop commits, and without a reservation.

Attempted commit#

The handover’s entry is one commit of three changes: the change of possession, which points box B at module 2’s possession state, and the reassignment of box B’s transport to module 2 and to module 2’s capability. The OGM reads each changed instance, and hands the triple store access module one update, which the store applies whole or not at all. The update removes

fci:BoxB cfc:hasPossessedWorkpiece fci:Module1_possession .
fci:BoxB_transport cfc:executedOn fci:Module1 .
fci:BoxB_transport cfc:implementsCapability fci:Module1_capability_box_transport .

and adds

fci:BoxB cfc:hasPossessedWorkpiece fci:Module2_possession .
fci:BoxB_transport cfc:executedOn fci:Module2 .
fci:BoxB_transport cfc:implementsCapability fci:Module2_capability_box_transport .

with the prefixes

PREFIX fci: <http://w3id.org/circularfactory/FlexConveyorInstances#>
PREFIX cfc: <http://w3id.org/circularfactory/Core#>

As the store returned it, and as the module received it. The report above is the same text, 3195 characters, SHA-256 aa4e9b936a316eb4e192237dff6f9bf15ec90a794a86d9065a4076e9af87cb8f, at every layer of the write path, byte for byte:

  1. The triple store access module’s own record of the store’s answer, which it logs at DEBUG: the status, 500, and the body unchanged, so that the record ends with the report.

  2. The error the access module raises, ShaclValidationError, whose report is the body of the store’s answer, as the middleware raised it out of its handover.

  3. The middleware’s record of the refused write, refused_writes, with the verb handover and the rules FlexConveyorModulePossessionShape at Module2.

  4. The answer the module’s giving side returns, StepResult.report, with the reason the triple store refused the handover, and the module’s warning, whose first line reads Module1: the triple store refused handing BoxB to Module2, by FlexConveyorModulePossessionShape at Module2; the recording keeps the report: and whose last lines are the report.

  5. The event commit_refused on module 1’s handover event stream, which the monitor shows, with the report in its refusal.

The recording checked the five copies against each other, and keeps the first one verbatim as skip-reserve.nq.

State after the refusal#

The same three queries, answered before the handover and after it, give the same rows: box B is still possessed by module 1, module 2 still possesses only box A, and the transport of box B is still executed on module 1, and still running.

Box B is still possessed by module 1.

Make it again#

On a triple store of your own, with TRIPLESTORE_URL, TRIPLESTORE_USERNAME and TRIPLESTORE_PASSWORD set, and with the name of a dataset that may be cleared in place of <dataset>:

TRIPLESTORE_ALLOW_DESTRUCTIVE=1 uv run python scripts/record_uc2_refusal.py --dataset <dataset>

It rewrites the page, the report and its Turtle copy. The live test makes the recording again without writing them, and compares its report with the committed one as RDF graphs:

TRIPLESTORE_ALLOW_DESTRUCTIVE=1 uv run pytest tests/test_uc2_recorded_refusal_live.py --dataset <dataset>
