jms_kapps.uc2.monitor.reads#

Every query the monitor sends. Each one reads; none writes.

The monitor does not choose what to show by reading the ontology: the classes and properties it reads are the use case’s own, named here, and no rdfs:subClassOf walk decides what is a module. A module is whatever the graph types as one of the three module classes.

Every IRI stays whole. A module, a box or a possessor is compared by its IRI as the graph holds it, never by a local name turned back into one; a local name is made only where a person reads it.

Each read keeps the query it sent last, exactly as the store received it, with when it went, how long the store took to answer and how many rows came back (GraphReads.sent): the monitor’s page shows them as “Queries sent”. (Added on 2026-10-08, jms_kapps 24, decided by Etienne on 2026-10-05: “we should at least then be able to expose the sparql queries that are sent”.)

Bases: object

A SPARQL query the monitor sent, the last time it sent it.

read is the read of the monitor that sent it: the name of its method in GraphReads. text is the query exactly as the store received it. sent is when (UTC, ISO 8601), duration how many seconds the store took to answer, and rows how many rows it answered; rows is None and error says why when the query failed.
