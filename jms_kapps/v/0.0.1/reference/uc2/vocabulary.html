jms_kapps.uc2.vocabulary#

The fc: terms use case 2 reads and writes, the IRIs of its individuals, and how a page names an IRI for a person: by its prefix or by its local name.

Middleware vocabulary (cfc:, svc:, mes:) is imported from the middleware, never spelled here, so the two cannot drift apart.

class jms_kapps.uc2.vocabulary.FC[source]#

Bases: object

Terms from ontology/flexconveyor_usecase.ttl, and the shapes a validation report names.

The shapes are in shapes/flexconveyor_usecase_shapes.ttl, in the same namespace.

jms_kapps.uc2.vocabulary.local_name(iri: str) → str[source]#

The part of iri after its last # or /, or iri itself if that is empty.

For a person to read only: a local name is never compared, and never turned back into an IRI.

jms_kapps.uc2.vocabulary.module_iri(n: int) → IRI[source]#

The IRI of FlexConveyorModule n.

jms_kapps.uc2.vocabulary.connection_iri(module_id: str, direction: str) → IRI[source]#

The IRI of the connection of the module module_id towards direction.

A module has at most one connection in each direction, so the direction names it.

jms_kapps.uc2.vocabulary.transit_time_literal(seconds: float) → Literal[source]#

A transit time as the graph holds it: an xsd:decimal of seconds.

jms_kapps.uc2.vocabulary.box_iri(n: int) → IRI[source]#

The IRI of Box n: a box named by a number, as a seed or a test names the boxes it places itself. The WarehouseManagementSystem names each box it spawns by a UUID (new_box_iri). (Changed on 2026-10-12, jms_kapps 92, decided by Sören on jms_kapps 85. Until then: “The IRI of Box n.”, the name of every box.)

jms_kapps.uc2.vocabulary.UUID_BOX_PREFIX = 'Box-'#

What the local name of a box named by a UUID starts with, before its UUID. (Added on 2026-10-12, jms_kapps 92; interim, jms_kapps 83.)

jms_kapps.uc2.vocabulary.uuid_box_iri(box_id: UUID) → IRI[source]#

The IRI of the box named by the UUID box_id: Box-<UUID>, in the instances’ namespace, as the WarehouseManagementSystem and the prefill name their boxes. (Added on 2026-10-12, jms_kapps 92; interim, jms_kapps 83.)

jms_kapps.uc2.vocabulary.new_box_iri() → IRI[source]#

The IRI of a new box, named by a new random UUID (version 4): how the WarehouseManagementSystem names each box it spawns, so that more than one middleware can create boxes without a shared number, and without reading the boxes in the graph.

(Added on 2026-10-12, jms_kapps 92, decided by Sören on jms_kapps 85: “a new box gets a UUID, so that more than one middleware can create boxes without a shared number”. Until then the WarehouseManagementSystem numbered a box after the highest-numbered box in the graph, through box_number, which read the number of a box named Box<n>; no code reads a box’s number any more. Interim, jms_kapps 83.)

jms_kapps.uc2.vocabulary.transport_iri(box: IRI) → IRI[source]#

The IRI that the WarehouseManagementSystem’s opening and the seed give the transport they create for box.

Only they call it, to choose the IRI of what they create. No party finds a transport by it: a box links to its transport by fc:hasTransport, so a party that holds a box reads the transport through the box. (Changed on 2026-10-06, jms_kapps 39, decided by Etienne. Until then it read: “The IRI of the BoxTransportOperation that carries box. A box has one, so it names it.”)
