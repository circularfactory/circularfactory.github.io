jms_kapps.common.supervision#

Starting, watching and stopping the processes of a use case, one per resource.

A launcher spawns each child through a Supervisor, which keeps one handle per child, keyed by the child’s resource IRI. The supervisor prints each child’s command line, in the form of the platform’s shell, so the child can be run on its own, and echoes every line the child writes with the child’s name in front. It reads each child’s state from the child’s service in the graph, through the one reader of a service (common.services): a child is live once its service is live and has registered every workflow the child registers, so that a caller can call any of them at once. It finds a child that exited without reading the graph, so that a read that hangs does not hide the exit. Its readiness gate, wait_until_ready, waits until every child is live. When a child turns failed, it prints one line with the child’s name and why, the exit code if its process exited, because a launcher without a page, as the bench launcher, shows nothing else. The pattern is the Launcher of the middleware’s transferunits demo.

A stop asks each child to stop, and the child deregisters its service in its own shutdown. A child that the stop kills at the stop timeout, or that exited without a stop, as a crash does, skipped that shutdown, and its service stays registered until its heartbeat is stale: see may_not_have_deregistered. A stop signal that fails is recorded, and the stop goes on to every later child. The reference page on stopping, docs/reference/stopping.md, lists every case that cannot deregister, with why. How a child is asked to stop, its process group and the form of its printed command line are the platform’s (jms_kapps.common.platforms). The process states, and the sets of them that a launcher asks about, are defined here and nowhere else.

A launcher clears the dataset it seeds, so it first checks that no other process’s service is live there: refuse_if_live, the one live-instance guard, which leaves out the resources of the launcher’s own processes that a stop killed or that exited on their own.

jms_kapps.common.supervision.refuse_if_live(services: Callable[[Collection[IRI]], Iterable[Service]], *, dataset: str, leave_out: Collection[IRI] = (), force: bool = False) → None[source]#

The live-instance guard: refuse to clear dataset while a service there is live.

A clear cannot be undone, so a launch clears only while no other process’s service is live in the dataset: another launcher’s, or that of a process run on its own from its printed command line, even on a resource this launcher stopped cleanly.

Parameters:

  • services – Reads the dataset’s live services.

  • dataset – The dataset’s name, for the refusal.

  • leave_out – The resources of this launcher’s own processes that may not have deregistered, because a stop killed them or they had exited on their own. Their services are this launcher’s own, and the seed clears what they left.

  • force – Go on whatever is live. Nothing is read then.

Raises:

  • LiveInstanceError – If another service is live, naming each live resource.

  • LaunchFailed – If the graph cannot say which services are live.

spawn(resource: IRI, name: str, command: list[str], *, workflows: Collection[IRI] = ()) → None[source]#

Start command as the process of resource, shown as name, which is live once its service has registered a workflow of each class in workflows.

A resource has one child for the life of the supervisor. A second handle under the same IRI would replace the first, and nothing could stop the first process any more.

Raises:

ValueError – If a child was spawned for resource already. Nothing is started then.

refresh() → None[source]#

Check every child’s process, then read the services once and set each state.

A child is live while its service is live and has registered every workflow the child registers, and it keeps its service’s address while it stays live. It has failed when its process exits without being told to, when its service stops being so, or when it has not turned live within the start timeout. A child that failed while it still runs turns live again once its service is.

An exit is this process’s own knowledge, so it is set before the graph is read, and it shows while the graph is away. A read that fails leaves every other state as it was, now unconfirmed, and raises its error again. Each turn to failed is printed, one line each.

heartbeat_error() → str | None[source]#

Why the latest read of the services failed, or None if it succeeded.

watch(interval: float = 1.0) → None[source]#

Watch the children every interval seconds, until stop_all, on two daemon threads: one finds the processes that exited, the other refreshes the states from the services.

A read of the graph can hang until the client’s own timeout gives up, 60 s. The first thread reads no graph, so it finds an exit within one interval however long a read hangs. The second keeps at most one read under way.

wait_until_ready(timeout: float | None = None, *, interval: float = 0.5) → None[source]#

The readiness gate: wait until every child is live, so that its service has an address, a fresh heartbeat and every workflow the child registers, and a caller can call any of them at once.

It reads the graph itself, every interval seconds, whether the watch runs or not. A read that fails is tried again until the wait runs out.

Parameters:

timeout – How long to wait at most, in seconds: the start timeout and one interval more if None, by when a child that has not turned live has failed.

Raises:

NotReady – If a child failed, or a stop reached it, before every child was live, naming it with its last output; or if not every child is live within timeout, naming each that is not, and why the last read of the graph failed if it did.

begin_stop() → None[source]#

Mark the stop as begun, before stop_all asks any child: from now on, a child whose process exits with code 0 before a stop asks it has stopped, not failed.

A stop signal can reach a child before the launcher asks it: a terminal’s Ctrl+C, or a SIGINT to the process group of ./run-uc2, reaches every process of the launcher’s process group at once, while the launcher still waits for the open connections of its own page. A child ends on Ctrl+C with code 0, once it has deregistered its service. An exit with any other code still turns it failed.

One assignment and no lock, so it is safe in a signal handler. (Added on 2026-10-10, jms_kapps 70.)

stop(resource: IRI) → None[source]#

Stop the child of resource, and wait until it has exited.

Raises:

KeyError – If no child was spawned for resource.

stop_all() → None[source]#

Stop every child, and wait until all of them have exited.

This is the ordered teardown: each child is asked to stop, in the order they were spawned, so that it deregisters its service in its own shutdown; they stop in parallel, within one stop timeout, and a child still running then is killed and reported. Every child of a use case is a middleware instance with no device process behind it, so there is no second tier to stop after them.

may_not_have_deregistered() → set[IRI][source]#

The resources whose child may have left its service live: the killed children, and those that exited without a stop asking them to (see _Child.may_not_have_deregistered).

snapshot() → list[ChildSnapshot][source]#

Every child as it is now, in the order they were spawned.
