jms_kapps.uc2.handshake#

What passes between two parties in a handover, and the handover itself.

Inside the FlexConveyor station, one hop is matched to the real conveyor, whose receiving module’s light barrier the Receive abstracts. The giving module asks the receiving module to reserve itself for the box, and the receiving module consents in its memory and answers at once. Once it has accepted, the giving module opens the middleware’s handover: its entry commits the change of possession, so the store admits or refuses it before anything moves, and the same commit assigns the box’s transport to the receiving module. Only then does the giving module convey the box, its own move and no workflow, and call the receiving module’s receive, the receiving module’s light barrier, which never refuses: the possession has already changed. The receiving module answers, then reads the box with its transport and carries the box on. Reserve and Receive are each one blocking call to the peer’s workflow, and each answers with a step result. A peer that the graph names no live workflow of, or whose call is refused, fails or times out, gives no answer: ask raises PeerUnreachable, whose message says why. A module leaves such a peer out for the box, with that message in its warning, and chooses again; the reason a failed transport records then names the destination and each module left out (no_live_route). The WarehouseManagementSystem’s reasons keep the message.

The WarehouseManagementSystem’s handover onto the station is its spawn, without the middleware’s handover: it asks the origin’s Reserve, creates the box directly on the origin, and notifies the origin, whose intake carries the box on as after a Receive. At the end, the destination hands the box back without the questions: the WarehouseManagementSystem answers no Reserve, and the store’s admission is the only check there. Giver.hand_over is the handover without the questions: every hop opens it, and the last handover, back to the WarehouseManagementSystem, is nothing more.

The step result is this use case’s own, not the middleware’s: the middleware’s workflow contract is arguments in, return value out, with no envelope. Status, time and progress are not in it, because the graph carries them.

The store’s refusal of a write is a type: the triplestore interface raises ShaclValidationError, which carries the store’s validation report verbatim, and the middleware and the object-graph mapper pass it on unchanged. Every write a party makes catches that type, and only that type. Any other error of the store, such as a dataset that does not exist, is raised.

hand_over(box: IRI, receiver: IRI, *, on_refusal: str, operation: IRI | None = None, transport: IRI | None = None, entry: Sequence[object] = (), arrived: Callable[[], object]=<function Giver.<lambda>>) → StepResult[source]#

Hand box to receiver: the possession changes first, then the box moves.

The possession extension’s handover commits the change of possession in its entry, together with the changes of entry, and operation becomes done in the same commit when it is given. If the store refuses the commit, nothing is written and nothing moves: the refusal is logged with its report, emitted as commit_refused on the party’s handover event stream, and the answer carries both. A failed precondition of the handover is refused the same way, before any write, and emits nothing: the store refused nothing. Otherwise the body runs: the move, then arrived, which calls the receiver’s Receive.

An error of the move, or of arrived, is raised as it is: the possession has changed by then, so the caller says what happened. A module writes nothing when arrived cannot reach the receiver, since the transport is the receiver’s by then; what the station records after the move itself failed is not decided yet.

Only a ShaclValidationError is the store’s refusal. Any other error of the store, such as a dataset that does not exist, is raised.

Parameters:

  • on_refusal – What the giver does next if the store refuses. The log line of the refusal says it.

  • transport – The transport of box, which an event of the refusal names.
