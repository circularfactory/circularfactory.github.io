kapps_triplestore_interface.graph_db#

class kapps_triplestore_interface.graph_db.GraphDB(*, endpoint: TripleStoreEndpoint, auth: BasicAuth | GDBTokenAuth, timeout: int = 60, named_graph: GraphNameLike | None = None, logger: logging.Logger | None = None)[source]#

Bases: RDF4JClient

The GraphDB adapter: a store of the contract TripleStore, on a GraphDB repository.

Build it from a TripleStoreEndpoint and an auth provider, GDBTokenAuth or BasicAuth. connect() builds it so and checks it; code above the interface types it as TripleStore. It provides methods for querying and updating data, manages authentication, the dataset, and a default named graph.

Parameters:

  • endpoint (TripleStoreEndpoint) – The store’s URL and dataset.

  • auth (BasicAuth | GDBTokenAuth) – The auth provider of the identity.

  • timeout (int) – The timeout of a request, in seconds. Defaults to 60.

  • named_graph (Optional[GraphNameLike]) – The default named graph, or None.

  • logger (Optional[logging.Logger]) – The logger. Defaults to one named after the class.

shapes_get() → Graph[source]#

The SHACL shapes that the store validates the dataset’s writes against, as a graph.

It is the read of what shapes_set writes: a document set and then read gives the same triples. A dataset without shapes gives an empty graph.

The adapter first reads the repository’s configuration, as shapes_set does, and raises TripleStoreNotSupportedError when it does not say that SHACL validation is on: such a dataset holds no shapes that validate anything, and the shapes graph is then plain data. Then it reads RDF4J’s shapes graph, rdf4j:SHACLShapeGraph, in one GET on the graph store, as Turtle.

Limit: only that one graph is read, the one that shapes_set writes. A repository configured with further shapes graphs validates against those as well, and their shapes are not in the answer.

Returns:

The shapes, of the type that graph_get gives.

Return type:

Graph

Raises:

  • TripleStoreNotSupportedError – If the configuration does not say that the dataset has SHACL validation. The shapes graph is not read.

  • AuthenticationError – If the store answers 401.

  • TripleStoreAccessError – If the store answers 403.

  • TripleStoreResponseError – If the store answers with any other error status. The message names the repository.

  • TripleStoreUnavailableError – If a request gets no answer. When the store closed the connection without an answer, the read is sent once more, on a fresh connection, and raises only if that fails as well.

ruleset_get() → str | None[source]#

The reasoning ruleset of the dataset, as GraphDB names it, or None.

For example “rdfsplus-optimized”, “owl2-rl” or “owl-max”. The adapter reads the ruleset parameter of the repository’s configuration, the request that shapes_set sends first. None means the configuration has no ruleset value. The method reports; which rulesets a caller supports is the caller’s rule.

Raises:

  • InvalidDatasetError – If the store answers 404 with Unknown repository: <dataset>.

  • TripleStoreResponseError – For any other error answer, typed by its status as every configuration read is, also a 404 with another answer.

  • TripleStoreUnavailableError – If the store gives no answer.

shapes_set(data: str, content_type: str) → None[source]#

Replace the SHACL shapes that the store validates the dataset against with data.

content_type is the media type of data, for example text/turtle; the store parses data. An empty document, or one of white space only, removes every shape.

GraphDB turns SHACL validation on only when a repository is created. On a repository without it, the shapes would be stored as plain data that validates nothing. So the adapter first reads the repository’s configuration, and raises TripleStoreNotSupportedError when it does not say that SHACL validation is on.

Then it replaces RDF4J’s shapes graph with data in one request, a PUT on the graph store, which the store commits whole or not at all. A store with SHACL validation checks the data of the dataset against the new shapes when it commits them, and refuses the replacement when the data violates them; the old shapes then stay, and the store validates against them as before (measured on GraphDB 10.8.5). An empty document is one DELETE of the shapes graph.

Raises:

  • TripleStoreNotSupportedError – If the configuration does not say that the dataset has SHACL validation. Nothing is written.

  • ShaclValidationError – If the store refused the replacement, because the data of the dataset violates the new shapes. Its report is the store’s validation report. The old shapes stay.

  • AuthenticationError – If the store answers 401.

  • TripleStoreAccessError – If the store answers 403.

  • TripleStoreResponseError – If the store answers with any other error status, for example to a document that it cannot parse. The message names the repository.

  • TripleStoreUnavailableError – If a request gets no answer. A write is not sent again.

validate(shapes: str, content_type: str) → str[source]#

Validate the whole dataset against shapes and return the store’s report verbatim.

shapes is a SHACL shapes document of the media type content_type, for example text/turtle. One POST to GraphDB’s validation endpoint, rest/repositories/<repository>/validate/text, with shapes as the body and Accept: text/turtle. The report’s format is the store’s: Turtle on GraphDB. The adapter returns the answer’s text unchanged; a conforming dataset gives a report with sh:conforms true, and a violation is part of the report, not an error.

An empty document, or one of white space only, validates against no shapes, and the report conforms.

This operation never changes the dataset, and never the shapes that the store validates writes against. The dataset need not have SHACL validation turned on.

Raises:

  • InvalidDatasetError – If the store answers 404: the dataset does not exist.

  • AuthenticationError – If the store answers 401.

  • TripleStoreAccessError – If the store answers 403.

  • TripleStoreResponseError – If the store answers with any other error status, for example to a document that it cannot parse. The message names the repository.

  • TripleStoreUnavailableError – If a request gets no answer.
