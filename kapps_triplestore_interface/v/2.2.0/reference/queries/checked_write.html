kapps_triplestore_interface.queries.checked_write#

The checked write: a write and its precondition in one update request.

The store answers every SPARQL update with success, whether the update changed anything or not. So a write that must report whether its precondition held cannot learn it from the response. A separate ASK before the write can be stale by the time the write runs.

A checked write puts the precondition into the WHERE of the update itself and adds one receipt triple to its INSERT. The receipt lands only when the WHERE matched, in the same commit as the change. One ASK for the receipt afterwards tells whether the write was applied, and a second request removes the receipt again.

Scope: the precondition reads the explicit triples of the target graph only. With a named graph, WITH <g> does that, because inferred triples are always in the default graph. Without one, USING <DEFAULT_GRAPH> restricts the WHERE to the explicit triples of the default graph, and the removals are written in GRAPH <DEFAULT_GRAPH> { … }, so that the delete acts on the same graph that the check read. A bare removal template would also remove copies of the triple in every named graph.

The contract: a normal return means that the store evaluated the precondition as true and committed the change. The store isolates commits only (“read committed”): another writer can commit between the evaluation of the WHERE and the commit of this write. An invariant that must hold under concurrent writers belongs in a SHACL shape, which the store checks when it commits.

kapps_triplestore_interface.queries.checked_write.render_update(old_triples: Sequence[Tuple[IRI | BNode, IRI, IRI | BNode | Literal]], new_triples: Sequence[Tuple[IRI | BNode, IRI, IRI | BNode | Literal]], named_graph: IRI | None, filters: Sequence[str] = (), receipt: URIRef | None = None, applied_at: str | None = None) → str[source]#

Render DELETE {old} INSERT {new} WHERE {old}.

Without receipt, the text is the unchecked update that triples_update has always sent. With it, the update also inserts the receipt, carries filters in its WHERE, and restricts its scope to the explicit triples of the target graph (see the module docstring).

A blank node in both lists is the same node and renders as the same variable. A blank node only in new_triples is minted with BIND(BNODE()).

kapps_triplestore_interface.queries.checked_write.checked_write(db: GraphDB, operation: str, old_triples: Sequence[Tuple[IRI | BNode, IRI, IRI | BNode | Literal]], new_triples: Sequence[Tuple[IRI | BNode, IRI, IRI | BNode | Literal]], named_graph: IRI | None, precondition: str, named_triples: Sequence[Tuple[IRI | BNode | None, IRI | None, IRI | BNode | Literal | None]], filters: Sequence[str] = ()) → bool[source]#

Send one update with its precondition and a receipt, then read and remove the receipt.

Parameters:

  • db (GraphDB) – The client.

  • operation (str) – The public function’s name, for messages.

  • old_triples (Sequence[Triple]) – Triples that must exist, and are removed.

  • new_triples (Sequence[Triple]) – Triples to insert.

  • named_graph (Optional[GraphName]) – The target graph, or None for the default graph.

  • precondition (str) – The precondition in words, for the error message.

  • named_triples (Sequence[PartialTriple]) – What the error names as .triples.

  • filters (Sequence[str]) – Further FILTER clauses of the precondition.

Returns:

True. A false precondition raises instead of returning False.

Return type:

bool

Raises:

  • PreconditionFailedError – The store found the precondition false; nothing was written.

  • GraphDbException – The store refused a request. A failure of the write itself propagates unchanged, and the receipt is not consulted: the store may still commit it.

  • requests.RequestException – A request got no answer, for example a timeout. For the write, as above: it propagates unchanged, the write is not sent again, and the receipt is not consulted.
